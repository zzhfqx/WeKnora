## 常用命令

### 重启基础设施（开发模式）

```bash
# 重启所有基础设施
make dev-restart

# 只重启某个服务，比如 postgres
docker compose -f docker-compose.dev.yml restart postgres
```

### 重启后端（开发模式，本地运行）

在运行 `make dev-app` 的终端按 `Ctrl+C` 停止，然后再次执行：

```bash
ss -tlnp | grep 8082   kill 进程
make dev-app
```

如果安装了 `air`，会自动重启，不需要手动操作。

### 重启前端（开发模式，本地运行）

前端支持热重载，大多数修改自动生效，无需重启。

**先检查前端是否在运行：**

```bash
ss -tlnp | grep 5173
```

- 有输出 → 前端在跑，进程名一般是 `node`
- 没输出 → 前端没启动，需要执行启动命令

如果确实需要重启，在运行 `make dev-frontend` 的终端按 `Ctrl+C` 停止，然后再次执行：

```bash
make dev-frontend
```

> 前端和后端一样是本地进程（不是 Docker 容器），所以 `make dev-status` 里看不到，只能用 `ss` / `ps` 检查。

### 常规模式常用重启

```bash
# 重启整个常规模式
docker compose restart

# 只重启 app（后端）
docker compose restart app

# 只重启 frontend（前端/nginx）
docker compose restart frontend
```

### 修改前端代码/图片后重新构建

常规模式下前端代码打包在 Docker 镜像里，改了代码或图片后需要**重新构建镜像**，光重启容器不生效。

```bash
cd /root/home/workspace_cribc/zzh_weknora/WeKnora

# 重新构建前端镜像（把新代码/图片打包进去）
docker compose build frontend

# 用新镜像重启前端容器
docker compose up -d frontend
```

> 只改前端不需要重启 app，数据库数据也完全不受影响。

**常用前端文件位置：**

- Logo 图片：`frontend/src/assets/img/weknora.png`（侧边栏 + 登录页共用）
- 浏览器标签图标：`frontend/public/favicon.ico`
- 新对话按钮图标：`frontend/src/assets/img/prefixIcon.svg`

## 配置说明

开发模式只需要在 `.env` 中添加一行配置：

```
DEV_REMOTE_HOST=<your-server-ip>
```

然后 `dev.sh` 脚本会自动把所有基础设施地址配置正确，不需要一个个手动改端口，非常方便。

## 关于数据隔离/共享

### 默认情况（推荐）：数据隔离

- 添加 `DEV_REMOTE_HOST=<your-server-ip>`，开发模式后端会自动连接开发模式自己独立的基础设施，数据和常规模式完全隔离。
- 常规模式和开发模式使用不同的数据库，互不影响，安全可靠。

### 特殊情况：共享常规模式数据库（不推荐，但可以实现）

- 如果注释掉 `DEV_REMOTE_HOST`（即 `# DEV_REMOTE_HOST=<your-server-ip>`），并且你的开发模式运行在和常规模式同一台机器上：
- 后端会连接到 `127.0.0.1` 的数据库，也就是常规模式的数据库，这样开发模式会共享常规模式的数据。
- ⚠️ **注意**：这种方式开发模式修改数据会直接影响常规模式，请谨慎使用。

如果你想连接其他外部数据库，只需要在 `.env` 中直接填写 `DB_HOST`, `DB_PORT` 等完整配置，`dev.sh` 会尊重你的配置。

## 注意事项

1. **完全隔离**：开发模式和常规模式使用独立的 Docker compose project（`weknora-dev` vs `weknora`）、独立的网络、独立的数据卷，互不影响
2. **开发体验**：
   - 前端代码修改后自动热重载，无需重启
   - 后端如果安装了 [air](https://github.com/air-verse/air)，代码修改后自动重启，否则手动 Ctrl+C 重启
   - 不需要每次修改都重新构建 Docker 镜像，开发速度快很多
3. **不影响常规版本**：两个项目文件夹完全独立，开发模式的修改不会影响常规版本
4. **后端端口说明**：默认开发模式后端端口为 **8082**（避免与常规部署的 8080 以及其他服务占用的 8081 冲突）
5. **Neo4j 可选**：如不需要知识图谱功能，在 `.env` 中设置 `NEO4J_ENABLE=false` 即可，不启动 Neo4j 也能正常使用核心功能

## 常见问题

### 常规部署前端502 / 登录页报错

**现象**：打开前端显示 nginx 502，或登录时 "An error occurred"。

**常见原因1：app 容器重启后 IP 变了，nginx 缓存了旧 DNS**

- 解决：重启前端容器
  ```bash
  docker compose restart frontend
  ```

**常见原因2：Neo4j 没启动，app 启动失败（NEO4J_ENABLE=true 时）**

- Neo4j 默认在 `neo4j` profile 里，`docker compose up -d` 不会自动启动。
- 确认：`docker ps | grep WeKnora-neo4j` 没有输出，说明没启动。

**方案1（推荐）：关闭知识图谱**

- `.env` 里设 `NEO4J_ENABLE=false`，然后 `docker compose restart app`
- 不需要 Neo4j，最省心

**方案2：用 profile 启动 Neo4j**

```bash
docker compose --profile neo4j up -d
```

- 以后所有 compose 操作都要带 `--profile neo4j`，否则 Neo4j 不会起来

### 修改后端端口后需要重新初始化数据库吗？

**不需要。**

- 修改后端端口（`config/config.yaml` 中的 `server.port`）只是改服务监听的端口号，和数据库完全无关
- 改完端口后只需要**重启后端**（`make dev-app`），前端 Vite 的代理配置（`frontend/vite.config.ts` 中的 `DEV_PROXY_TARGET`）也要同步修改
- 数据库数据存储在 Docker volume（`weknora-dev_postgres-data-dev`）里，只要不删除 volume，数据一直保留
- `make dev-start` / `make dev-app` / `make dev-frontend` 三步操作都不会删除数据

### 如何启动开发模式的 Neo4j？

**Neo4j 默认不启动**，它在 `neo4j` / `full` profile 里，需要手动启用。

#### 方式一：只启动 Neo4j（推荐）

```bash
cd /root/home/workspace_cribc/my_weknora/WeKnora
docker compose -f docker-compose.dev.yml -p weknora-dev --profile neo4j up -d neo4j
```

- 端口：HTTP `17474`，Bolt `17687`
- 默认账号：`neo4j` / `password`
- 数据存在独立 volume `neo4j-data-dev` 中，不影响常规部署

#### 方式二：启动全部可选服务（包含 Neo4j）

```bash
make dev-start DEV_ARGS=--full
```

> ⚠️ 会同时启动 MinIO、Qdrant、Milvus、OpenSearch、Langfuse 等所有可选服务，比较重，按需选择。

#### 启动后还要做的事

1. 修改 `.env`，把 `NEO4J_ENABLE=false` 改为 `NEO4J_ENABLE=true`
2. 重启后端（`make dev-app` 那个终端 Ctrl+C 再重新执行）

> `docker compose restart neo4j` 不管用 — 只能重启已存在的容器，容器不存在时什么也不做。必须用 `up -d` 创建并启动。

#### 重启后端时报 "address already in use" 怎么办？

启用 Neo4j 后需要重启后端，重启时可能遇到端口被占：

```
FATAL: Failed to run application: failed to start server: listen tcp 0.0.0.0:8082: bind: address already in use
```

**原因**：之前的后端进程没杀掉，`pkill -f "cmd/server"` 有时匹配不到（进程名显示为 `server`）。

**解决方法**：

```bash
# 查看谁占着 8082
ss -tlnp | grep 8082

# 用 PID 杀掉（把 520902 换成实际 PID）
kill 520902

# 或者直接按端口杀（最简单）
fuser -k 8082/tcp

# 然后再启动
make dev-app
```

## 开发模式后台运行（nohup，关闭终端不失效）

默认的 `make dev-app` 和 `make dev-frontend` 都是**前台运行**的，关闭终端进程就会退出。
如果希望像常规部署一样后台常驻（关闭终端不影响），可以使用后台运行模式（基于 nohup + PID 文件管理）。

### 一键启动全部（最推荐）

```bash
cd /root/home/workspace_cribc/my_weknora/WeKnora

# 一键启动基础设施 + 后端 + 前端（全部后台运行）
make dev-bg

# 一键停止所有服务
make dev-bg-stop
```

### 分别管理前后端

**后端：**

```bash
make dev-app-bg          # 后台启动后端（日志写入 log.log）
make dev-app-bg-stop     # 停止后端
make dev-app-bg-restart  # 重启后端
make dev-app-bg-status   # 查看后端运行状态
make dev-app-bg-logs     # 实时查看后端日志
```

**前端：**

```bash
make dev-frontend-bg          # 后台启动前端（日志写入 log_frontend.log）
make dev-frontend-bg-stop     # 停止前端
make dev-frontend-bg-restart  # 重启前端
make dev-frontend-bg-status   # 查看前端运行状态
make dev-frontend-bg-logs     # 实时查看前端日志
```

### 日志与 PID 文件

| 文件 | 说明 |
| ---- | ---- |
| `log.log` | 后端运行日志（和之前 `make dev-app 2>&1 \| tee log.log` 效果一致） |
| `log_frontend.log` | 前端运行日志 |
| `pid.app` | 后端进程 PID 文件 |
| `pid.frontend` | 前端进程 PID 文件 |

查看日志：

```bash
# 实时滚动查看后端日志
tail -f log.log

# 实时滚动查看前端日志
tail -f log_frontend.log
```

### 后台模式特点

- ✅ **关闭终端不失效**：使用 `nohup` 后台运行，终端断开连接进程继续运行
- ✅ **日志写入文件**：后端日志写入 `log.log`，方便排查问题
- ✅ **PID 文件管理**：自动记录进程 PID，启停命令精准控制
- ✅ **端口占用检测**：启动前自动检测并清理端口占用（如 8082 / 5173）
- ✅ **环境变量兼容**：完全复用 `.env` / `.env.local` 配置，和前台模式行为一致
- ✅ **优雅停止**：先发送 SIGTERM 优雅退出，超时自动强制 kill 兜底
- ✅ **启动失败检测**：启动后自动检测进程存活，失败则打印日志尾部便于排查

> ⚠️ 注意：后台模式下后端不会使用 `air` 热重载（`go run` 直接运行）。如果需要热重载，请使用前台模式 `make dev-app`。
