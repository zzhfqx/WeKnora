# 法规场景本体改造方案

## 一、概述

本文档描述将现有 WeKnora Wiki 系统改造为支持"法规场景本体"的技术方案。

**核心思想**：从自顶向下的分类学本体（L1领域分类→L2实体类），转向自底向上、从文档出发的场景化本体（法规→条款→业务对象）。

**验证状态**：已通过手动数据导入验证，现有数据库表结构完全兼容，无需新增字段。

---

## 二、数据模型分析

### 结论：现有三张表完全够用，不需要新增字段

| 表 | 用途 | 兼容性 |
|----|------|--------|
| `wiki_pages` | 页面主表 | ✅ 完全兼容。法规摘要用 `summary` 类型，条款用 `concept` 类型，业务对象用 `entity` 类型 |
| `wiki_folders` | 目录文件夹 | ✅ 完全兼容。一级目录"法规/条款/业务对象"，二级目录为文档名（仅法规下有） |
| `wiki_page_relations` | 语义关系 | ✅ 完全兼容。三类关系：`from_document`（条款来自法规）、`defined_in`（业务对象规定于条款）、`mentioned_in`（业务对象涉及于法规） |

### 目录结构映射

```
wiki_folders 层级：
├── 法规 (L1, depth=1)
│   ├── 意外险监管办法 (L2, depth=2)
│   ├── 互联网人身险通知 (L2, depth=2)
│   └── ...（共11个文档子目录）
├── 条款 (L1, depth=1)
│   └── （直接挂37个条款页，平铺，无L2）
└── 业务对象 (L1, depth=1)
    └── （直接挂18个实体页，平铺，无L2）
```

### Slug 命名规范

| 类型 | page_type | slug 前缀 | 示例 |
|------|-----------|-----------|------|
| 法规摘要 | `summary` | `summary/doc-xxx-...` | `summary/doc-001-accident-insurance-regulation` |
| 条款 | `concept` | `clause/<doc-topic>-c-xxx` | `clause/accident-insurance-c-0106` |
| 业务对象 | `entity` | `entity/<kebab-name>` | `entity/pricing-review-mechanism` |
| 首页 | `index` | `index` | `index` |

## 四、代码改造点

### 4.1 提取层改造（Pass 0）

**文件**：`internal/agent/prompts_wiki.go`

**改造内容**：
- 新增"法规场景提取"提示词，提取内容从"实体/概念"改为"条款 + 业务对象"
- 提取输出结构：
  ```json
  {
    "clauses": [
      {
        "clause_id": "C-0106",
        "article_number": "七条",
        "title": "附加费用率上限",
        "content_summary": "...",
        "topic_tags": ["产品管理", "费用率"],
        "slug": "clause/accident-insurance-c-0106"
      }
    ],
    "business_objects": [
      {
        "obj_id": "BO-001",
        "name": "意外伤害保险",
        "name_en": "Accident Insurance",
        "description": "...",
        "slug": "entity/accident-insurance",
        "attributes": [...],
        "appearing_clauses": ["clause/..."]
      }
    ]
  }
  ```

### 4.2 目录生成改造（Taxonomy）

**文件**：
- `internal/agent/prompts_wiki.go` 中的 `WikiTaxonomyPlanPrompt`
- `internal/application/service/wiki_ingest_taxonomy.go`

**改造内容**：
- 目录结构从"领域分类→实体类"改为"法规/条款/业务对象"三层
- 法规二级目录 = 每篇文档名
- 条款和业务对象的二级目录可选（当前平铺，后续可按主题分类）

### 4.3 页面生成层改造

**文件**：`internal/application/service/wiki_ingest.go`

**改造内容**：
- 新增法规摘要页生成逻辑（page_type: summary）
- 新增条款页生成逻辑（page_type: concept）
- 业务对象页复用现有 entity 页面生成逻辑
- 页面内容模板化：
  - 法规摘要：基本信息表 + 概要 + 条款列表 + 业务对象列表
  - 条款页：来源 + 内容 + 涉及业务对象 + 相关条款
  - 业务对象页：定义 + 属性表 + 规定于 + 涉及法规

### 4.4 关系生成改造

**文件**：`internal/application/service/wiki_ingest.go`

**改造内容**：
- 新增三类关系的自动生成：
  1. 条款 → `from_document` → 法规（每条款自动建立）
  2. 业务对象 → `defined_in` → 条款（根据 appearing_clauses）
  3. 业务对象 → `mentioned_in` → 法规（根据 source_docs）
- 关系写入 `wiki_page_relations` 表（已有，无需改表）

### 4.5 知识库配置扩展

**文件**：
- `internal/types/wiki_page.go` 中的 `WikiConfig`
- `internal/types/knowledgebase.go`

**改造内容**：
- 在 `WikiConfig` 中新增 `scene_type` 字段，标识本体场景类型
  - `generic`（默认，现有通用提取）
  - `regulation`（法规场景）
- 不同场景使用不同的提取提示词和目录结构

### 4.6 Slug 规范扩展

**文件**：`internal/types/wiki_page.go`

**改造内容**：
- 条款页使用 `clause/` 前缀的 slug（目前用 concept 类型，slug 用 clause 前缀也可以）
- 确认 `IsValidWikiPageType` 不需要新增类型（条款用 concept，业务对象用 entity，法规模块用 summary）
