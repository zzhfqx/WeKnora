# WeKnora 检索接口汇总

本文档整理 WeKnora 所有检索类接口，涵盖知识库、文档、FAQ、Wiki、知识图谱、历史对话等多个维度的检索能力。

---

## 接口总览

| 接口名称 | 方法 | 路径 | 检索方式 | 返回粒度 | 核心用途 |
|---------|------|------|---------|---------|---------|
| [混合检索（知识库级）](#1-混合检索知识库级) | POST/GET | `/knowledge-bases/{id}/hybrid-search` | 向量 + 关键词 RRF 融合 | Chunk（片段） | 知识库内语义+关键词混合检索 |
| [问答管线检索](#2-问答管线检索knowledge-search) | POST | `/knowledge-search` | 向量 + Rerank 重排 + 阈值过滤 | Chunk（片段） | 高质量问答检索（有 Rerank 过滤） |
| [文档搜索](#3-文档搜索knowledgesearch) | GET | `/knowledge/search` | 纯文本关键词匹配 | Knowledge（文档） | 按关键词搜文档列表 |
| [FAQ 搜索](#4-faq-搜索) | POST | `/knowledge-bases/{id}/faq/search` | 混合搜索 + 标签优先级 | FAQ 条目 | FAQ 知识库问答检索 |
| [Wiki 页面搜索](#5-wiki-页面搜索) | GET | `/knowledgebase/{kb_id}/wiki/search` | PostgreSQL 正则匹配 | Wiki 页面 | Wiki 页面全文检索 |

| [历史对话搜索](#7-历史对话搜索) | POST | `/messages/search` | 关键词 / 向量 / 混合 | 消息记录 | 历史对话消息检索 |

## 1. 混合检索（知识库级）

### 基本信息

| 项 | 值 |
|----|----|
| **接口路径** | `POST /api/v1/knowledge-bases/{id}/hybrid-search` |
| **备用方法** | `GET /api/v1/knowledge-bases/{id}/hybrid-search`（兼容旧客户端） |
| **路由定义** | `internal/router/routes_knowledge.go:227` |
| **Handler** | `internal/handler/knowledgebase.go:318` → `KnowledgeBaseHandler.HybridSearch` |
| **请求体类型** | `internal/types/search.go:230` → `types.SearchParams` |
| **鉴权方式** | JWT Bearer / API Key |
| **权限要求** | Viewer+ 且对知识库有 read 权限 |
| **核心用途** | 在单个知识库内执行向量+关键词混合搜索，返回相关的文本片段 |

### 检索原理

向量检索（pgvector HNSW）+ 关键词检索（ParadeDB BM25），通过 **RRF（Reciprocal Rank Fusion，倒数排名融合）** 合并结果。

RRF 公式：
```
score = vector_weight / (K + vector_rank) + keyword_weight / (K + keyword_rank)
```

默认参数：K=60，向量权重=0.7，关键词权重=0.3。

### 路径参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | ✅ | 知识库 ID |

### Query 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `resource_urls` | string | ❌ | 文件引用形式：`handle` / `public`，默认 `handle` |

### 请求体参数

| 字段 | JSON 字段名 | 类型 | 必填 | 默认值 | 说明 |
|------|------------|------|------|--------|------|
| QueryText | `query_text` | string | ✅* | - | 搜索文本（提供 query_embedding 且关闭关键词时可空） |
| QueryEmbedding | `query_embedding` | float32[] | ❌ | - | 预计算查询向量，提供则跳过向量化 |
| MatchCount | `match_count` | int | ❌ | - | 返回结果条数 |
| VectorThreshold | `vector_threshold` | float | ❌ | 0 | 向量相似度阈值，低于过滤 |
| KeywordThreshold | `keyword_threshold` | float | ❌ | 0 | 关键词得分阈值 |
| DisableKeywordsMatch | `disable_keywords_match` | bool | ❌ | false | 关闭关键词检索，仅用向量 |
| DisableVectorMatch | `disable_vector_match` | bool | ❌ | false | 关闭向量检索，仅用关键词 |
| KnowledgeIDs | `knowledge_ids` | string[] | ❌ | - | 限定只搜某些文档 |
| TagIDs | `tag_ids` | string[] | ❌ | - | 按标签过滤（FAQ 优先排序） |
| ScopeTagIDs | `scope_tag_ids` | string[] | ❌ | - | 标签范围过滤 |
| OnlyRecommended | `only_recommended` | bool | ❌ | false | 仅返回推荐结果 |
| KnowledgeBaseIDs | `knowledge_base_ids` | string[] | ❌ | - | 跨知识库搜索（需同一向量模型） |
| SkipContextEnrichment | `skip_context_enrichment` | bool | ❌ | false | 跳过上下文增强（不取父/相邻/关联 chunk） |

### 返回结果

```json
{
  "success": true,
  "data": [
    {
      "id": "chunk-uuid",
      "content": "片段内容...",
      "knowledge_id": "文档ID",
      "chunk_index": 0,
      "knowledge_title": "文档标题",
      "start_at": 0,
      "end_at": 500,
      "seq": 0,
      "score": 0.5123,
      "match_type": 0,
      "sub_chunk_id": null,
      "metadata": { ... },
      "chunk_type": "text",
      "parent_chunk_id": "父chunkID",
      "knowledge_base_id": "知识库ID",
      ...
    }
  ]
}
```

### match_type 含义

| 值 | 含义 |
|----|------|
| 0 | 向量匹配 |
| 1 | 关键词匹配 |
| 2 | 混合匹配（两边都命中） |

## 2. 问答管线检索（/knowledge-search）

### 基本信息

| 项 | 值 |
|----|----|
| **接口路径** | `POST /api/v1/knowledge-search` |
| **路由定义** | `internal/router/routes_chat.go:121` |
| **Handler** | `internal/handler/session/qa.go:719` → `session.Handler.SearchKnowledge` |
| **请求体类型** | `internal/handler/session/types.go:73` → `SearchKnowledgeRequest` |
| **鉴权方式** | JWT Bearer / API Key |
| **权限要求** | Viewer+ |
| **核心用途** | 问答管线的 chunk 检索，带 Rerank 重排和阈值过滤，质量更高但召回更少 |

### 检索原理

1. **向量检索**召回候选 chunk（默认 topK=50）
2. **Rerank 模型**（bge-reranker-v2-m3）对候选做语义重排
3. **阈值过滤**（默认 0.2），低于阈值的全部丢弃
4. 返回通过阈值的结果

> ⚠️ 与 hybrid-search 的核心区别：多了 Rerank 重排和严格阈值过滤，宁可少返回也不返回不相关结果。

### 请求体参数

| 字段 | JSON 字段名 | 类型 | 必填 | 说明 |
|------|------------|------|------|------|
| Query | `query` | string | ✅ | 搜索文本 |
| KnowledgeBaseID | `knowledge_base_id` | string | ❌ | 单个知识库 ID（向后兼容） |
| KnowledgeBaseIDs | `knowledge_base_ids` | string[] | ❌ | 多个知识库 ID（推荐） |
| KnowledgeIDs | `knowledge_ids` | string[] | ❌ | 限定搜某些文档 |
| TagIDs | `tag_ids` | string[] | ❌ | 标签 ID 过滤 |
| MentionedItems | `mentioned_items` | object[] | ❌ | 带范围的标签提及 |

> ⚠️ `knowledge_base_id`、`knowledge_base_ids`、`knowledge_ids`、`tag_ids` 至少提供一个。

### 返回结果

```json
{
  "success": true,
  "data": [
    {
      "id": "chunk-uuid",
      "content": "片段内容",
      "knowledge_id": "文档ID",
      "knowledge_title": "文档标题",
      "score": 0.8521,
      "chunk_type": "text",
      "knowledge_base_id": "知识库ID",
      ...
    }
  ]
}
```

## 5. Wiki 页面搜索

### 基本信息

| 项 | 值 |
|----|----|
| **接口路径** | `GET /api/v1/knowledgebase/{kb_id}/wiki/search` |
| **路由定义** | `internal/router/routes_knowledge.go:328` |
| **Handler** | `internal/handler/wiki_page.go:1030` → `WikiPageHandler.SearchPages` |
| **鉴权方式** | JWT Bearer / API Key |
| **权限要求** | Viewer+ 且对 KB 有 read 权限 |
| **核心用途** | 在 Wiki 页面中进行全文搜索，返回匹配的 Wiki 页面列表 |

### 检索原理

PostgreSQL `~*` 正则匹配（大小写不敏感），按匹配位置加权排序：
- 标题匹配 → 权重 4
- slug 匹配 → 权重 3
- 摘要匹配 → 权重 2
- 内容匹配 → 权重 1

> ⚠️ 纯文本正则匹配，不是向量语义检索。搜索词必须作为子串出现在页面内容中。

### 路径参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `kb_id` | string | ✅ | 知识库 ID |

### Query 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `q` | string | ✅ | - | 搜索关键词 |
| `limit` | int | ❌ | 10 | 返回条数（最大 50） |

### 返回结果

```json
{
```

## 附录：检索管线名词解释

| 术语 | 英文 | 说明 |
|------|------|------|
| Chunk | 块 / 片段 | 文档切分后的最小文本单元，是向量检索的基本单位 |
| 向量检索 | Vector Search | 将查询向量化后，在向量空间中找最相似的 chunk（余弦距离） |
| 关键词检索 | Keyword Search | 基于 BM25 或正则的文本匹配，匹配字面值 |
| 混合检索 | Hybrid Search | 向量 + 关键词结合，取长补短 |
| RRF | Reciprocal Rank Fusion | 倒数排名融合，用排名而非原始分数合并多路结果 |
| Rerank | 重排序 | 用交叉编码器模型对候选结果做二次精排，准确率更高但更慢 |
| Embedding | 嵌入 / 向量化 | 将文本转换为高维向量的过程 |
| HNSW | Hierarchical Navigable Small World | 近似最近邻向量索引算法，pgvector 使用 |
| BM25 | Best Matching 25 | 经典关键词匹配算法，ParadeDB 使用 |
