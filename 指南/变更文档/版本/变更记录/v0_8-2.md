## 一、大文件上传修复（已完成升级 ✅）

### 背景

v0.8.0 修改版中，我们通过在 `uploadKnowledgeFile` 中硬编码 `{ timeout: 300000 }` 解决了大文件上传超时问题。

v0.8.2 官方实现了更优雅的**动态超时方案**：根据 FormData 中文件大小自动计算超时，小文件用下限（5 分钟），大文件按 10MB/min 线性增长。

### 调整内容

#### 1.1 新增动态超时工具模块

**文件**：`frontend/src/utils/requestTimeouts.ts`（**新增**，从 v0.8.2 官方移植）

**核心 API**：

| 函数/常量 | 说明 |
|----------|------|
| `UPLOAD_TIMEOUT_FLOOR_MS` | 上传超时下限：5 分钟 |
| `uploadPayloadBytes(data)` | 计算 FormData 中所有 Blob/File 的总字节数 |
| `uploadTimeoutMs(data)` | 动态计算超时：`max(5min, 文件大小 / 10MB * 60s)` |
| `isTimeoutError(error)` | 判断请求失败是否为超时（覆盖 ECONNABORTED / ETIMEDOUT / message 含 timeout） |

#### 1.2 `postUpload` 统一应用动态超时

**文件**：`frontend/src/utils/request.ts`（修改）

在 `postUpload` 函数中新增动态超时：
```typescript
return instance.post(url, data, {
  timeout: uploadTimeoutMs(data),  // 新增
  ...config,                         // 显式 config.timeout 仍可覆盖
  // ...
})
```

**优势**：所有调用 `postUpload` 的上传接口（知识文件上传、技能包上传、模型上传等）自动获得动态超时，无需每个接口单独配置。

#### 1.3 移除 `uploadKnowledgeFile` 中的硬编码超时

**文件**：`frontend/src/api/knowledge-base/index.ts`（修改）

```diff
- return postUpload(url, formData, onProgress, { timeout: 300000 });
+ return postUpload(url, formData, onProgress);
```

改为依赖 `postUpload` 的统一动态超时。

#### 1.4 保留：上传失败原因提示增强

**文件**：`frontend/src/views/knowledge/KnowledgeBase.vue`（保留并优化）

- `getUploadFailureReason`：详细的失败原因分类（重复文件、超时、网络错误、后端 message）**全部保留**
- **优化**：超时判断从内联检查改为复用 `isTimeoutError` 工具函数（覆盖更多超时场景，如 `ETIMEDOUT`）
- `showUploadResultMessages`：批量上传失败时显示失败文件详情列表 **全部保留**

#### 1.5 保留：后端上传耗时日志

**文件**：`internal/application/service/knowledge_create.go`（保留）

- 开始时记录文件名 + 大小
- 重复文件跳过时记录耗时
- 完成时记录总耗时

官方 v0.8.2 没有对应的中文日志增强，继续保留我们的实现。

### 方案对比

| 维度 | v0.8.0 修改版（固定 5 分钟） | v0.8.2 修改版（动态超时） |
|------|---------------------------|------------------------|
| 小文件（<10MB） | 5 分钟 | 5 分钟（相同） |
| 100MB 文件 | 5 分钟（可能不够） | 10 分钟 |
| 200MB 文件 | 5 分钟（不够） | 20 分钟 |
| 覆盖范围 | 仅知识文件上传 | 所有 `postUpload` 调用 |
| 可扩展性 | 每个接口手动加 | 统一处理，自动生效 |
