# WeKnora 解析引擎能力对比表

> **编制日期**：2026-10-12
> **数据来源**：WeKnora 源码实际集成实现 + 实际部署配置
> **当前可用引擎（7个）**：
> - ✅ 内置 (DocReader)、Simple、MarkItDown
> - ✅ MinerU（自部署，backend=pipeline，公式识别✅ 表格识别✅，语言=ch）
> - ✅ PaddleOCR-VL（自部署，印章识别✅ 图表识别✅）
> - ✅ OpenDataLoader
> - ❌ 不可用：anydoc、WeKnora Cloud、MinerU Cloud、PaddleOCR-VL Cloud

---

## 一、引擎概览

| 引擎 | 类型 | 调用接口 | 核心定位 | 支持格式数 |
|------|------|---------|---------|-----------|
| **内置 (DocReader)** | Python gRPC 服务 | gRPC | 通用 Office/PDF 解析主力 | 多 |
| **Simple** | Go 原生 | 进程内 | 纯文本 + 图片直通，零依赖 | 少（md/txt/csv/json/图片/音频） |
| **MarkItDown** | Python 库（DocReader 内） | gRPC | 微软开源转换工具 | 中（PDF/Office/HTML） |
| **MinerU** | 自托管 HTTP | `POST /file_parse` | PDF 高质量版面分析 + OCR + 公式 + 表格 | 10 种（pdf/图片/doc/docx/ppt/pptx） ⚠️ WeKnora 未启用 Excel，官方实际支持 |
| **PaddleOCR-VL** | 自托管 HTTP | `POST /layout-parsing` | OCR + 版面分析 + 印章/图表区域识别 | 6 种（pdf/图片） |
| **OpenDataLoader** | Java 服务 | - | PDF 版面分析 | 1 种（PDF） |

> **重要说明**：
> - PaddleOCR-VL 的名字里虽然有 "VL"，但 WeKnora 集成中 `promptLabel` 硬编码为 `"ocr"`，是**纯 OCR + 版面分析**，不是 VLM 视觉理解，不能做图片内容描述
> - VLM 图片理解是 WeKnora 中独立的"图像处理/VLLM 视觉模型"配置（如 DeepSeek-OCR），在 docparser 之后的多模态后处理阶段
> - **MinerU 对 Excel 的支持说明**：MinerU 官方服务本身支持 xlsx/xls 解析（版面分析路线），但 **WeKnora 集成时硬编码的 `FileTypes` 列表中没有加入 xlsx/xls**，因此前端下拉中 MinerU 不出现在 Excel 选项里。属于"WeKnora 未启用"而非"MinerU 不支持"。如需启用，在 `internal/infrastructure/docparser/engines.go` 的 mineruEngine.FileTypes() 中追加 `"xlsx", "xls"` 即可
> - **PaddleOCR-VL 对 Excel 的支持说明**：PaddleOCR-VL 官方本身就只支持 PDF + 图片格式（官网明确标注），不支持任何 Office 文档格式。属于"官方不支持"，WeKnora 侧无法通过修改配置启用

## 二、各格式解析能力对比

### 2.1 Excel（.xlsx / .xls）

| 能力维度 | 内置 (ExcelParser) | MarkItDown | Simple | MinerU | PaddleOCR-VL | OpenDataLoader |
|---------|-------------------|-----------|--------|--------|-------------|---------------|
| **.xlsx 支持** | ✅ 原生 | ✅ 支持 | ❌ | ⚠️ WeKnora未启用 | ❌ 不支持 | ❌ 仅 PDF |
| **.xls 支持** | ✅（xlrd/LibreOffice转） | ✅（LibreOffice转） | ❌ | ⚠️ WeKnora未启用 | ❌ | ❌ |
| **多 Sheet** | ✅ 全部遍历 | ✅ | - | ⚠️ 待验证 | - | - |
| **输出格式** | 行级键值对（`列: 值`） | Markdown 表格 | - | ⚠️ 版面分析→Markdown | - | - |
| **合并单元格** | ✅ 自动填充值 | ⚠️ 取决于库 | - | ⚠️ 待验证 | - | - |
| **公式** | ⚠️ 只保留结果值 | ⚠️ 取决于库 | - | ⚠️ 走OCR只看到结果 | - | - |
| **图表 (Chart)** | ❌ 主动丢弃（`xlsx_merge.py` 明确删除 charts） | ⚠️ 通常只提文本 | - | ✅ 版面分析可识别图表 | - | - |
| **嵌入式图片** | ❌ 不提取（只过滤 DISPIMG 函数文本） | ⚠️ 不确定 | - | ⚠️ 走版面分析可以提取 | - | - |
| **宏 (VBA)** | ❌ 忽略 | ❌ | - | ❌ | - | - |
| **首行当表头** | ⚠️ 默认关闭，需手动开 `xlsx_first_row_as_header` | ⚠️ 取决于库 | - | ⚠️ 自动识别 | - | - |
| **加密文件** | ❌ 无法解析 | ❌ | - | ❌ | - | - |

> **Excel 结论**：
> - 当前 WeKnora 可用的 Excel 引擎只有"内置"和"MarkItDown"。内置引擎输出行级键值对（适合检索），MarkItDown 输出 Markdown 表格（更可读）
> - **MinerU 官方实际支持 Excel**（版面分析/OCR 路线），但 WeKnora 集成时未将 xlsx/xls 加入支持列表，因此前端不显示。如果手动加入 `FileTypes`，MinerU 可以用版面分析方式解析 Excel，对图表的处理可能优于内置引擎（内置直接删图表，MinerU 走版面分析可以看到图表）
> - **PaddleOCR-VL 官方本身就不支持 Excel**，只支持 PDF + 图片，WeKnora 侧无法通过修改启用
> - **内置引擎的图表是硬伤**——主动删除 charts，即使配了 VLLM 也没用（无图可看）；如果用 MinerU 走版面分析路线，图表反而能被 VLLM 理解

### 2.2 PPT（.pptx / .ppt）

| 能力维度 | 内置 (走 MarkItDown) | MarkItDown | Simple | MinerU | PaddleOCR-VL | OpenDataLoader |
|---------|---------------------|-----------|--------|--------|-------------|---------------|
| **.pptx 支持** | ✅ | ✅ | ❌ | ✅ | ❌ 不支持 | ❌ 仅 PDF |
| **.ppt 支持** | ✅（LibreOffice 转） | ✅（LibreOffice 转） | ❌ | ✅ | ❌ | ❌ |
| **文本提取** | ✅ 完整提取 | ✅ | - | ✅ | - | - |
| **输出格式** | Markdown | Markdown | - | Markdown + 图片 | - | - |
| **表格** | ✅ 转 Markdown 表格 | ✅ | - | ✅ | - | - |
| **图片提取** | ✅（含 pptx_media 光栅化） | ✅ | - | ✅ | - | - |
| **矢量图 (WMF/EMF)** | ✅ ImageMagick 光栅化 | ✅ | - | ⚠️ 不确定 | - | - |
| **图表 (Chart)** | ⚠️ 数据可能部分提取，视觉丢失 | ⚠️ | - | ⚠️ 走版面分析路线，识别程度取决于 MinerU | - | - |
| **SmartArt** | ⚠️ 部分文本，结构丢失 | ⚠️ | - | ⚠️ | - | - |
| **动画/过渡** | ❌ 全部丢失 | ❌ | - | ❌ | - | - |
| **演讲者备注** | ⚠️ 取决于 markitdown 库 | ⚠️ | - | ⚠️ 不确定 | - | - |
| **音视频** | ❌ 忽略 | ❌ | - | ❌ | - | - |
| **嵌入式 OLE 对象** | ❌ 不支持 | ❌ | - | ❌ | - | - |
| **+ VLLM 后处理** | 图片可被理解 | 图片可被理解 | - | 图片可被理解 | - | - |

> **PPT 结论**：内置/MarkItDown/MinerU 都能解析。图表数据可能不全，但图片能提取出来，配合 VLLM 后处理可以"看懂"图表内容。PaddleOCR-VL 不直接支持 PPT 格式。

### 2.3 PDF

| 能力维度 | 内置 (DocReader) | MarkItDown | Simple | MinerU | PaddleOCR-VL | OpenDataLoader |
|---------|-----------------|-----------|--------|--------|-------------|---------------|
| **文本型 PDF** | ✅ 高质量提取 | ✅ | ❌ | ✅ 直接提文本 | ✅ OCR 提取 | ✅ |
| **扫描型 PDF** | ❌ 无 OCR 能力 | ❌ | ❌ | ✅ **专业 OCR + 版面分析** | ✅ **OCR + 版面分析** | ⚠️ |
| **表格** | ✅ | ⚠️ | - | ✅ **表格结构识别（有线/无线）** | ✅ 表格识别 + 合并 | ✅ |
| **公式** | ⚠️ 文本提取 | ❌ | - | ✅ **公式识别（可输出 LaTeX）** | ❌ 仅 OCR 文字 | ⚠️ |
| **图片/插图** | ✅ 提取 | ✅ | - | ✅ 提取 | ✅ 提取 | - |
| **多栏排版** | ⚠️ 可能串行错乱 | ⚠️ | - | ✅ **版面分析还原阅读顺序** | ✅ 版面分析 | ✅ |
| **页眉页脚** | ⚠️ 可能混入正文 | ⚠️ | - | ✅ 可识别并过滤 | ✅ markdownIgnoreLabels 过滤 | - |
| **印章识别** | ❌ | ❌ | - | ❌ | ✅ **印章识别（默认开启）** | ❌ |
| **图表识别** | ❌ | ❌ | - | ⚠️ | ✅ **图表区域识别（你已开启）** | ❌ |
| **输出格式** | Markdown | Markdown | - | Markdown + 结构化 | Markdown | - |

> **PDF 结论**：
> - 纯文本 PDF → 内置/MarkItDown 足够，轻量快速
> - 扫描版 PDF / 复杂排版 → **MinerU 最强**（版面分析+公式+表格全齐），PaddleOCR-VL 做 OCR 和版面分析也够用，且有印章识别
> - PaddleOCR-VL 的"图表识别"是识别图表区域位置，不是理解图表内容；配 VLLM 后才能真正看懂图表

## 四、引擎选择建议（按场景）

| 场景 | 首选引擎 | 次选引擎 | 理由 |
|------|---------|---------|------|
| **日常 Office 文档（Word/PPT/Excel）** | 内置 (DocReader) | MarkItDown | 最稳定，功能全面，无需额外服务 |
| **扫描版 PDF / 复杂排版 PDF** | MinerU | PaddleOCR-VL | MinerU 版面分析最专业，公式/表格都强；PaddleOCR-VL 多了印章识别 |
| **纯文本 PDF / 简单文档** | 内置 | MarkItDown | 轻量快速，够用 |
| **图片文档 / 截图（需 OCR）** | PaddleOCR-VL | MinerU | PaddleOCR-VL OCR + 印章识别，MinerU 也够用 |
| **图片文档 / 需理解内容** | PaddleOCR-VL + VLLM | MinerU + VLLM | OCR 引擎只负责提文字，内容理解靠 VLLM 后处理 |
| **Excel 数据文件** | 内置 (ExcelParser) | MarkItDown | 内置行级输出更适合检索，MarkItDown 表格更可读。图表是内置的硬伤（主动删除），如需图表识别可手动启用 MinerU（WeKnora 未默认启用） |
| **PPT 演示文稿** | 内置/MarkItDown | MinerU | 内置够用，复杂图表多的话试 MinerU + VLLM |
| **带印章的文档（扫描件）** | PaddleOCR-VL | - | 独有印章识别能力 |
| **极简场景（纯文本/图片直通）** | Simple | - | 零依赖，速度最快 |

## 五、关键边界与坑

### 通用坑
1. **anydoc 不可用**：当前环境没编译 anydoc，进程内快速解析这条路走不通，所有复杂格式都要走 DocReader 或外部服务
2. **旧版 .xls / .ppt 依赖 LibreOffice**：没有 `soffice` 的话旧格式解析会失败
3. **PaddleOCR-VL ≠ VLM**：名字里有 VL 但实际是 OCR + 版面分析，不要混淆
4. **VLLM 是独立的后处理阶段**：不是 docparser 引擎的一部分，是解析完了再对图片做理解
5. **引擎选择是多层 fallback**：Go 侧一层，Python DocReader 侧又一层，排查问题时两边都要看

### Excel 特有坑
1. **内置引擎图表硬伤**：内置（ExcelParser）主动删除 charts，MinerU 走版面分析可以识别图表（但 WeKnora 默认未启用）
2. **默认首行不当表头**：与直觉相反，需手动配置 `xlsx_first_row_as_header: true`
3. **PaddleOCR-VL 官方不支持 Excel**：只支持 PDF + 图片，别配错规则
4. **MinerU 支持 Excel 但 WeKnora 未启用**：如需启用，在 `internal/infrastructure/docparser/engines.go` 的 mineruEngine.FileTypes() 中加 `"xlsx", "xls"`
5. **嵌入式图片提取**：builtin 引擎不提，MinerU 走版面分析可以提取（需手动启用）

### PPT 特有坑
1. **矢量图需 ImageMagick**：WMF/EMF 格式的矢量图需要 `/usr/bin/convert` 才能光栅化
2. **动画全部丢失**：Markdown 无法表示动画
3. **嵌入式对象无解**：PPT 里嵌的 Excel/Word 文档解析不了
4. **PaddleOCR-VL 不直接支持 PPT**：要先转成 PDF 或图片再走 PaddleOCR-VL

### PDF 特有坑
1. **扫描版 PDF 必须配 OCR 引擎**：MinerU 或 PaddleOCR-VL，不然就是空文档
2. **公式识别是 MinerU 强项**：学术/技术文档首选 MinerU
3. **多栏排版要版面分析**：纯文本提取会串行错乱
4. **印章识别只有 PaddleOCR-VL 有**：对合同/公文类扫描件有用

### 图片特有坑
1. **OCR 引擎不能理解图片内容**：只能提取文字，要看懂图片得配 VLLM
2. **PaddleOCR-VL 的图表识别 ≠ 图表理解**：只是识别区域位置和提取文字
3. **图片理解完全取决于 VLLM 模型能力**：配的模型越强，理解越准
